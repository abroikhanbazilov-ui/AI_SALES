# WhatsApp AI Sales Agent

Локальный FastAPI-сервис для холодной WhatsApp-рассылки через GreenAPI, обработки ответов AI-ботом и ведения базы контактов в SQLite.

Подробная бизнесовая и техническая документация проекта: [PROJECT_DOCUMENTATION.md](PROJECT_DOCUMENTATION.md).

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть панель: http://127.0.0.1:8000

При первом открытии сервис перенаправит на `/setup`. Там нужно один раз создать единственную админ-учетку. После этого все страницы и API, кроме GreenAPI webhook, требуют входа.

## Порядок работы

1. Войти в админку.
2. В переключателе проекта выбрать `Автоскоринг` или `Второй продукт`.
3. В `Проекты` настроить название продукта, тип воркфлоу, файл КП и промпт выбранного проекта.
4. В `Настройки` заполнить `GreenAPI ID`, `GreenAPI token`, AI-провайдера и ключи OpenAI или DeepSeek.
5. В `Excel` загрузить файл, выбрать один или несколько столбцов с номерами, при желании выбрать организацию, имя и столбцы `Контекст / сигналы` для signal-based рассылки.
6. Нажать `Импортировать и проверить WhatsApp`.
7. В `Рассылка` задать лимит сообщений и случайную задержку, затем запустить кампанию.
8. В `AI-режим` включить обработку входящих ответов.

При включении AI-режима и при старте сервиса, если AI был включен ранее, сервис сначала подтягивает последние входящие из GreenAPI за период `Синхронизация истории, мин`. Это нужно, чтобы после остановки/рестарта не начинать диалог заново, а продолжить по сохраненному этапу контакта, истории сообщений и статусу отправки КП.

Для чистого теста новой базы нажать `Очистить тестовую базу` на вкладке `Excel` или `Обнулить базу` на вкладке `Контакты`. Это очищает только активный проект: контакты, ответственных, диалоги, кампании и связанные события. Настройки, ключи, КП и Excel-файлы остаются.

## Локальная проверка диалогов

Перед деплоем стоит прогонять оба слоя проверки:

```bash
python -m unittest tests.test_dialog_behavior
python scripts/simulate_dialogs.py
```

`tests.test_dialog_behavior` проверяет детерминированные ветки и статусы, а `scripts/simulate_dialogs.py` гоняет локальные sales-сценарии на временной БД: transfer offer, self-LPR, общий интерес с переходом в созвон и objection по существующей CRM.

Текущая версия `scripts/simulate_dialogs.py` прогоняет 30 разных сценариев вокруг нового two-step opener: permission-based первое касание, yes-path по автокредитному направлению, self-LPR, objections, handoff, КП и scheduling.

Отдельно в диалоговой логике зафиксирован регресс на фразы вроде `уточните подробнее` и `расскажите подробнее`: бот не должен завершать такой разговор пустым reply и обязан дать короткое пояснение с следующим вопросом.

## Что хранится локально

- `data/agent.sqlite3` - настройки, проекты, контакты, кампании, сообщения, контекст диалогов и хеш пароля администратора.
- `uploads/` - временно загруженные Excel-файлы.
- `Коммерческое Предложение.html` - КП, которое отправляется через `sendFileByUpload`.
- Вкладка `Логи` показывает системные события из таблицы `event_logs`: импорт, проверки WhatsApp, кампании, AI, входящие/исходящие и ошибки.
- Заинтересованные лиды проходят через `interest_dialog`: сервис сначала задает discovery-вопрос или переводит разговор в scheduling, а не шлет КП автоматически из-за одного слова `интересно`. Handoff-уведомление на номер из настройки `Номер для зацепок` не дублируется по одному контакту.
- Для `autoscore_responsible` первое касание теперь двухшаговое: сначала короткий permission-based вопрос по автокредитному направлению, затем yes/no-проверка `у вас есть продажи авто через автокредит?`, и только после первого подтверждения бот представляется и раскрывает решение.
- Если клиент просит `подробнее` или `уточните`, бот отвечает по сути и продолжает диалог; silent-close оставлен только для совсем коротких terminal-ack сообщений после уже завершенного шага.
- Если клиент мягко отказывается (`не актуально`, `пока не интересно`), контакт закрывается в `not_interested / closed_no_interest`, но без шаблонного хвоста вроде `если захотите вернуться к вопросу` или `я на связи`.
- Если бот уже предложил `пришлю короткое КП сюда в WhatsApp?`, то короткие подтверждения вроде `Ок`, `Да` и разговорные команды вроде `Отправляй!` считаются согласием на отправку, а не поводом повторять тот же вопрос.
- Вкладка `CRM` показывает канбан сделок по этапам. Клик по карточке открывает полную историю WhatsApp-диалога по контакту.

## GreenAPI

Сервис использует:

- `checkWhatsapp` для проверки номеров после импорта.
- `sendMessage` для текстовых сообщений.
- `receiveNotification` и `deleteNotification` для чтения входящих через long polling.
- `lastIncomingMessages` для восстановления входящих после простоя или перед включением AI-режима.
- `sendFileByUpload` для отправки HTML-файла КП.

Если в кабинете GreenAPI будет настроен webhook, можно направить его на `/api/webhook/greenapi`.
